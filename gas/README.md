# GAS のコードの作成例：YouTube の数値を、毎朝スプレッドシートに蓄積する

> **作成例です。** 本物の YouTube と GAS では動かしていません。本番では、依頼者のチャンネルで動作を確かめてから使います。
> 鍵、本物のチャンネルの ID、本物のスプレッドシートの ID は含めていません。設定はスクリプトのプロパティから読みます。

## 仕組み

```
YouTube Analytics API（日次の指標、検索キーワード、視聴者）─┐
YouTube Data API（動画の一覧、題名、公開日）────────────────┴→ GAS（毎朝6時台に自動実行）→ スプレッドシート（日次の蓄積）→ Looker Studio
```

- 毎朝、動画の一覧を取り直し、**動画ごとの日次の指標の直近5日分**を取り直して上書きします。API の数値は2〜3日遅れて確定するため、前日の分だけを足す作りでは、ずれた数値がそのまま残ります。
- 検索キーワードは、チャンネル全体と動画ごとに、直近28日と全期間の2つを取ります。
- 視聴者は、国、市区町村（条件つき）、年齢と性別を取ります。
- Looker Studio はスプレッドシートを読むだけです。レポートの表示のたびに API を呼ばないため、表示が速く、上限の範囲に収まる作りです。

## ファイル

| ファイル | 役割 |
|---|---|
| `appsscript.json` | タイムゾーン Asia/Tokyo、V8、高度なサービス（YouTube Analytics API v2、YouTube Data API v3）、権限の明示 |
| `Config.js` | スクリプトのプロパティの読み込み、シートの名前と列、処理の決まり（5日、4分30秒、25件、3回） |
| `Videos.js` | チャンネルの全部の動画の一覧（uploads のプレイリスト → 50件ずつ） |
| `Analytics.js` | YouTube Analytics API の呼び出し、一時的なエラーの試し直し |
| `Sheets.js` | 書き込み（日付＋動画の ID で上書き）、週次のまとめ（月曜始まり）、実行の記録 |
| `Runner.js` | 毎朝の処理の本体。時間で区切り、続きから再開する |
| `Triggers.js` | 毎朝の自動実行と、続きの実行の予約 |
| `Notify.js` | 失敗したときのメールの通知（許可の期限切れは文面を分ける。1日に1回まで） |
| `Setup.js` | 初回の設定、スプレッドシートのメニュー |
| `tests/` | Node.js での単体テスト（GAS の機能は偽物に差し替え） |

## シート

| シート | 列 |
|---|---|
| `videos` | 動画のID、題名、公開日、長さ（秒）、サムネイルのURL、最終の更新日時 |
| `daily_video` | 日付、動画のID、再生回数、総再生時間（分）、平均視聴時間（秒）、平均視聴率（%）、高評価、コメント、登録者の増加、登録者の減少、確定前 |
| `weekly_channel` | 週の始まり（月曜）、日数、再生回数、総再生時間（分）、確定前を含む |
| `search_channel` | 期間、キーワード、再生回数、総再生時間（分）、順位 |
| `search_video` | 期間、動画のID、キーワード、再生回数、順位 |
| `audience_country` / `audience_city` / `audience_age_gender` | 期間ごとの国、市区町村、年齢と性別の割合 |
| `run_log` | 実行の日時、種類、処理した件数、かかった時間（秒）、結果、エラーの内容 |

検索のシートの最後の行は「（上位25件に入らない検索）」です。検索からの再生の合計と、上位25件の合計の差です。

## 設定の手順（依頼者が許可のボタンを押すまで）

作業は、**依頼者の Google アカウント**で行います。GAS とスプレッドシートは依頼者のドライブに置くため、契約が終わっても、依頼者の手元で動き続けます。パスワードを預かる必要はありません。

1. 依頼者のドライブに、新しいスプレッドシートを作ります。
2. 「拡張機能 → Apps Script」を開き、このフォルダのファイルを同じ名前で作ります（`appsscript.json` は、プロジェクトの設定で「appsscript.json をエディタで表示」をオンにしてから置き換えます）。
3. 「プロジェクトの設定 → スクリプト プロパティ」に、次を入れます（コードには書きません）。
   - `SPREADSHEET_ID`：手順1のスプレッドシートの ID
   - `NOTIFY_EMAIL`：失敗のお知らせを受け取るメールアドレス
   - `HISTORY_START_DATE`：過去の分を取り込み始める日（例：`2025-11-01`）
4. スプレッドシートを開き直すと、メニュー「YouTube レポート」が出ます。「初回の設定」を押します。
5. 許可の画面が出ます。依頼者のアカウントを選びます。
   - 「このアプリは Google で確認されていません」と出ます。依頼者のために作ったスクリプトで、一般に公開するアプリではないためです。「詳細」→「（プロジェクトの名前）に移動」を押します。
   - 求める権限は、YouTube の数値の**読み取りだけ**（`yt-analytics.readonly`、`youtube.readonly`）と、スプレッドシートへの書き込み、自動実行の予約、通知のメールの送信です。動画の編集やコメントの書き込みの権限は求めません。
6. 「許可」を押すと、シートが作られ、毎朝の自動実行が入り、過去の分の取り込みが始まります。過去の分は、何回かに分けて自動で進みます（`run_log` に記録が残ります）。

## Looker Studio のつなぎ方

1. Looker Studio で「データを追加 → Google スプレッドシート」を選び、`daily_video`、`videos`、`search_channel`、`search_video`、`audience_*` をそれぞれデータソースにします。
2. `daily_video` と `videos` を「動画のID」で結合し、題名とサムネイルを付けます。
3. 期間の選択と、動画の絞り込みのコントロールを、ページの上に置きます。
4. 「確定前」の列で、直近の3日の色を変えます。
5. 第1段階では、標準の YouTube のコネクタで主要な指標を先に出し、第2段階で、このスプレッドシートの検索キーワードと日次の蓄積を足します。

## 実装の決まり

- **直近の取り直し**：毎朝、直近5日分を取り直し、「日付＋動画の ID」で上書きします。行は増えません。直近の3日には「確定前」の印を付けます。
- **6分の制限**：実行の開始から約4分30秒で区切り、どこまで処理したか（段階と動画の位置）を PropertiesService に残して、1分後に続きを実行する予約（`ScriptApp.newTrigger('continueRun').timeBased().after(60 * 1000)`）を入れます。続きが全部終わったら、予約を消します。
- **初回の過去の分の取り込み**：`HISTORY_START_DATE`（それより後に公開した動画は公開日）から昨日まで。同じ区切りの仕組みで、何回かに分けて進みます。
- **検索キーワード**：`maxResults=25`、`sort=-views` を必ず付けます。検索の合計（`dimensions=insightTrafficSourceType` の `YT_SEARCH` の行）も取り、上位25件との差を「上位25件に入らない検索」として残します。
- **空の結果**：年齢と性別、市区町村が、しきい値のため空で返ってきても、エラーにせず「データなし（しきい値未満）」と記録します。市区町村が使えないチャンネルでは、ほかの処理を止めずに記録だけ残します。
- **再試行**：一時的なエラー（500番台、レート制限）は、待ち時間を延ばしながら3回まで試します。許可の切れや引数の誤りは、試し直しません。
- **失敗の通知**：例外が出たら、`run_log` に残し、`NOTIFY_EMAIL` にメールを送ります。許可の期限切れは文面を分け、「メニューの『もう一度許可する』を押してください」と案内します。同じ種類の失敗の通知は、1日に1回までです。
- **同時の実行**：LockService で、毎朝の実行と続きの実行が重ならないようにします。

## 注意点

- API の仕様は、公開されている仕様にもとづいています。ご契約の後に、依頼者のチャンネルで実際に確かめます。
- 市区町村の単位で、どこまで返ってくるかは、チャンネルの規模によります。ご契約の後に確かめてから、レポートに入れるかを決めます。
- 日本の都道府県の単位の集計は、API にありません（地域の集計はアメリカの州だけが対象）。国の単位と、市区町村の単位で代えます。
- 年齢と性別は、ログインしている視聴者の割合だけです（人数ではありません）。

## テスト

```bash
npm ci
npx vitest run gas/tests
```

`gas/*.js` を Node.js の `vm` で1つの文脈に読み込み（GAS では全部のファイルが同じ場所に並ぶため）、YouTubeAnalytics、YouTube、SpreadsheetApp、PropertiesService、ScriptApp、MailApp、Utilities、LockService を偽物に差し替えて確かめます。時計も偽物にして、API を呼ぶたびに進めます。

- 直近5日分の取り直しで、同じ日と動画の行が増えずに置き換わる（直近の3日に「確定前」の印）
- 約4分30秒で区切り、続きの位置が残り、1分後の続きの実行で残りが処理され、予約が消える
- 初回の取り込みは、HISTORY_START_DATE（と公開日）から昨日まで
- 検索キーワードの取得に、`maxResults=25` と `sort=-views` が付く
- 動画ごとの検索キーワードの取得に、`video==` の絞り込みが付く
- 「上位25件に入らない検索」が、合計との差で正しく計算される（マイナスにはしない）
- 年齢と性別が空で返ってきても、例外にならず「データなし」と記録される
- 一時的なエラーは試し直し、3回失敗したら記録して通知する
- 許可の期限切れのときは、試し直さず、再許可を案内する通知になる
- 同じ失敗の通知が、1日に2回送られない
- 週次の集計が、月曜始まりで正しくまとまる
- コードの中に、鍵や ID が書かれていない。YouTube の権限は読み取りだけ
- スクリプトのプロパティが足りないと、分かる言葉で止まる
